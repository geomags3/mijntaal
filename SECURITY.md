# Security

Keep personal installations private. Each user supplies provider credentials through Settings; encrypted credentials and generated recordings belong to that installation.

Do not publish keys, encrypted credential copies, cookies, account identifiers, private backups or deployment secrets. Never expose the development server or trust the Sites identity header outside a trusted authentication boundary.

For a suspected vulnerability, use the repository's private vulnerability-reporting channel if enabled. Do not include credentials or private user data in a public issue. If no private channel is available, ask the maintainer for a private contact without posting exploit details or personal data.

Automated tests and dependency advisory checks reduce risk but do not establish that an installation is secure. Provider access and hosted authentication require separate verification.
